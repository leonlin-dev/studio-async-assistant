# 00 · 愿景与问题定义

## 一句话愿景

让每个用户只关心他想关心的内容；AI 助手负责其余内容，并完成用户期待的交付物的产出。

## 核心张力（设计必须回答的问题）

1. **异步意味着什么**
   - 用户发起请求后不在线、不等待；助手在后台持续工作。
   - 工作跨度可能是分钟级（跑任务）到天级（跟踪一件演化中的事）。
   - 异步带来三个根本难题：**中途需要决策怎么办**、**结果如何送达且不被淹没**、**用户回来时如何低成本恢复上下文**。

2. "只关心他想关心的内容"意味着什么
   - 关注（attention）是用户显式声明 + 助手推断的共同产物，且随时间演化。
   - 助手必须有一种可校准的"关注模型"：什么该打扰用户、什么该自行处置、什么该记下来待问。

3. "交付物"意味着什么
   - 交付物是用户期待的具体产物（一份报告、一次修复、一个可运行的东西、一条结论）。
   - 交付物必须有可验收的定义，否则"完成"无法判定，异步就没有意义。

## 本项目要产出的东西（设计阶段）

一份原理性方案，回答：

- 任务的表示与生命周期（如何声明、拆解、执行、验收、交付）。
- 用户关注模型（什么进入用户视野，什么不进入）。
- 异步控制流（阻塞点、升级/委托/搁置策略）。
- 交付物契约（验收标准、格式、送达方式）。
- 记忆与上下文恢复（长周期任务的连续性）。
- 信任与权限的渐进放大（异步时代理权限如何安全授予）。
