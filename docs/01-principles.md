# 01 · 原理性方案

状态：**v1.0-提案（proposal）**。每条原理的裁决见 `docs/decisions/`，全部为**建议裁决，待用户逐项否决/批准**；被否决的项打回推敲队列，格式不变（主张 → 论据 → 反方 → 裁决）。

## P1 · 任务是唯一的一等公民 → [D03](decisions/2026-10-10-D03-p1-tasks-oq1-admission.md)

统一表示 + 分级仪式：一切工作统一为任务（`draft → active → blocked → delivered → accepted/closed`），仪式按规模分三级——微任务（免契约）/ 标准任务（契约前置）/ 战役（任务组合）。

## P2 · 关注模型 → [D02](decisions/2026-10-10-D02-p2-attention-model.md)

三层：显式订阅（不占预算，聚合呈现）+ 推断关注（digest-first，确认才升级，纠正回写记忆）+ 免打扰预算（只约束直接打断；耗尽则 ask 降级为 park + 合入摘要）。关注粒度 = 主题。

## P3 · 异步控制流三出口 → [D01](decisions/2026-10-10-D01-p3-control-flow.md)

任何决策点只有问（ask）/赌（commit）/搁（park）三个合法出口。委托 = 任务拆解不是出口；abort 分来源（自查可弃留痕，用户任务只能搁置）；默认偏向由信任度动态决定；赌需三重门槛（可回滚、留痕、按影响面限额）。

## P4 · 交付物契约前置 → [D04](decisions/2026-10-10-D04-p4-contract-first.md)

active 之前必有契约：形式 + 验收标准 + 送达方式。验收三级判定（机检 → LLM 裁判留痕 → 用户终验）；探索型契约三要素（问题、完成判据、边界）；自查契约自拟自批留痕可否决。

## P5 · 记忆按用户视角组织 → [D05](decisions/2026-10-10-D05-p5-memory-oq4-compression.md)

主索引 = 用户关注主题，不按任务历史。压缩红线：决策留痕/契约/验收逐字永不压缩；过程上下文可摘要；恢复界面 = 一页状态。

## P6 · 信任渐进放大 → [D06](decisions/2026-10-10-D06-p6-trust.md)

信任矩阵 = 任务类型 × 出口档位。降：一次否决降一级，两次否决只问不赌；升：N 次连续验收（N 随影响面增大）；冷启动最保守档。为 P3 默认偏向、D03-b 自查并发上限供能。

## P7 · 可中断、可观察、可接管 → [D07](decisions/2026-10-10-D07-p7-observe-oq3-delivery.md)

随时观察/中断/接管；接管携带完整异步上下文，会话结束任务回到异步流。送达（收件箱，唯一真源）与打扰（推送，受预算）彻底分离。

## 已裁决的开放问题

- **OQ2** 多任务冲突 → D08-a：契约声明所有权，他属对象强制 park+问，无锁无合并。
- **OQ3** 送达通道 → D07-b：收件箱唯一真源 + 推送通知层（预算内）。
- **OQ4** 上下文压缩 → D05-b：证据（留痕/契约/验收）永不压缩，过程可摘要。
- **OQ5** 多用户隔离 → D08-b：关注/记忆/收件箱按用户隔离，共享区仅显式发布。
