# 02 · 原理性方案 v1.0（整合稿）

状态：**提案，待用户逐项批准**。本文是 D01–D08 的单一视图：系统由什么组成、一个任务如何流过它、各机制如何互相供能。

## 一、系统的五个部件

```

│                        用户（只看视野内的东西）             │
│   视野 = 订阅主题(聚合) + 预算内推送 + 一页状态 + 收件箱    │
└───────────────▲────────────────────────────▲───────────────┘
        送达/打扰(D07-b)                  问 ask / 否决 / 纠正
┌───────────────┴────────────────────────────┴───────────────┐

├────────────────────────────────────────────────────────────┤
```

## 二、一个任务的一生（全部机制串起来）

1. **诞生**：用户一句话发起，或助手自查发现（后者需过 D03-b 三重门槛）。
2. **立契**：标准任务必须有契约（形式+验收+送达，D04）；探索型任务用三要素探索契约。自查任务助手自拟自批留痕。
3. **执行**：走三出口（D01）。每个决策点：够熟且可回滚 → 赌（留痕）；不确定 → 查信任矩阵定默认偏向；需要用户 → 问（占预算，预算尽则降级 park+入摘要）；等外部 → 搁。
4. **冲突**：触碰他属交付物 → 强制 park+问（D08-a）。
5. **交付**：按 D04-a 三级验收（机检 → LLM 裁判 → 用户终验，仅用户发起任务必经终验）。
6. **送达**：永远进收件箱；预算内才推送（D07-b）。
7. **结算**：验收通过 → 该类型信任升一档的计数+1；否决 → 降档（D06-b）。任务归档，仅关注相关事实提升进记忆（D05-a）。

## 三、机制的互供能关系（方案的承重结构）

- **P6 信任矩阵是能源核心**：P3 的默认偏向、D03-b 的自查并发上限、D01-d 的赌限额全部消费它；D04 验收结果喂养它。
- **D02 预算是注意力稀缺器**：约束 ask 与推送；预算压力倒逼合并与摘要，D05-b 的"一页状态"与收件箱聚合是它的泄压阀。
- **D05 压缩红线是审计底座**：因为决策留痕永不压缩，P6 的升降级才有证据、P7 的接管才有上下文。
- **D08 所有权是并发裁决器**：让 park 成为合法稳态而非失败，三出口模型在多任务下无需锁即闭合。

## 四、不变式（实现时任何设计不得违反）

1. 任何任务在任意时刻必处于问/赌/搁之一所导致的状态，且可审计。
2. 用户发起的任务不可被助手关闭，只能搁置并说明。
3. 不可逆动作永不赌，只能问。
4. 决策留痕、契约、验收结果永不压缩、永不静默删除。
5. 送达与打扰分离：送达无条件，打扰必有预算。
6. 跨用户可见性必经显式发布。
7. 用户可随时观察/中断/接管任何任务，接管不销毁异步上下文。
